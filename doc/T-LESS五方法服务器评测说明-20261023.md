本次交付独立工具包 `F:\projects\M3T\tless-five-methods-kit.tar`，服务器目录为 `/home/jyj/Projects/tless-tracker-comparison`。复用已验证的原工业比较包冻结源码及依赖，不覆盖RBOT入口、原算法目录或旧结果。服务器构建与图像小测仍需实际执行；本地没有T-LESS RGB图像，不预填准确率。

## 1. 先明确本轮实验是什么

五方法：RBGT、SRT3D、ICG、ICG+、我们的改进版，全部仅使用相同RGB及已知CAD。本轮是**GT初始化的真实静态视点环跟踪补充实验**，不是实际工件运动视频，也不是官方BOP定位排行榜结果。

| 项目 | 本轮固定设置 |
|---|---|
| 场景 | 全20个真实Primesense测试场景 |
| 原图 | 每场景504张，720×540、8-bit RGB |
| 视点 | 每场景7个俯仰层：75/65/55/45/35/25/15°，每层72视点 |
| 物理实例 | 20场景合计138个，每帧GT索引通过世界位姿一致性验证 |
| 目标视点环 | 138×7＝966个；五方法4,830个作业 |
| 初始化 | 每实例/俯仰环内，按原图ID首个可见比例≥0.1的视点真值初始化 |
| 顺序 | 从初始化视点开始，环内按原始ID循环排列；不跨俯仰层拼接 |
| 评价 | 其余71视点；每方法68,586帧，总计342,930个方法目标帧 |
| 低可见度 | 所有后续视点保留；其中2,244帧/方法原始可见比例<0.1，另分组报告 |
| 主成功条件 | 对称感知MSSD/模型直径≤0.1 |
| 重置 | 先保存估计、计入失败，再用当前帧GT重置；清空预测历史 |
| 其他误差 | 原生像素MSPD、MSSD/直径与MSPD阈值曲线；不计算或冒充官方BOP AR/VSD |
| 预热 | 每环前10个评价帧只从计时剔除；每方法58,926个计时样本 |
| 迭代/输入 | 7次对应×2次更新，200模型点；原方法各自RGB RBOT参数 |
| 深度/遮挡信息 | 不输入传感器深度、不用其他物体GT建模遮挡 |

27个模型有对称标注，其中11个有连续轴。对称集保留旋转和平移偏置，连续轴按BOP常见的`max_sym_disc_step=0.01`生成315个离散旋转；评分使用全部官方 `models_eval` 顶点，不以随机点子集代替。公式参考[BOP对称变换实现](https://github.com/thodan/bop_toolkit/blob/master/bop_toolkit_lib/misc.py)与[MSSD/MSPD定义](https://github.com/thodan/bop_toolkit/blob/master/bop_toolkit_lib/pose_error.py)。

这些阈值、初始化和重置是在运行方法前固定的协议。主分母包含不可见/重遮挡视点，不能把GT重置成绩写成无人工干预的持续工作能力；0.1直径也不是某一实际装配工位的公差。

## 2. 已实际核验的序列可靠性

读取了全部20场景相机、目标GT、可见度标注和30个CAD/评价模型，合计122个输入文件绑定完整SHA256。

- 同类多实例并未仅凭列表序号假定关联：先将每帧每实例变换到世界坐标，逐一核验与首帧一致，当前数据的最大平移差约 `7.03e-10 m`，最大旋转矩阵元素差约 `1.40e-8`，GT类别顺序也全程一致。更换文件或关联失效会拒绝运行。
- 每俯仰环核验相机中心方位递进、闭环间隔和相机姿态变化。最大相邻姿态变化为8.2293°（scene_13、35°层、图315→316），并非所有步长都严格5°；没有把它插值为平滑视频。环内验证上限固定10°。
- 低可见度帧保持真实输入和相同时间顺序，不在跟踪过程中跳帧。GT辅助视点划分/实例关联和初始化都在报告中明确标出。
- CAD以毫米转换为米，保留原点、坐标轴、三角面顺序及原始顶点法线，不居中或重缩放。

## 3. 变化内参：在线整数平移加填充

实际数据焦距固定，变化仅在主点，且偏移全为整数。统一相机为：

```text
width=757, height=635
fx=1075.65091572, fy=1073.90347929
cx=399.06888344, cy=328.72159802
dx=cx_common-cx_original，dy=cy_common-cy_original
```

每帧读入原720×540图像，按dx/dy平移到757×635画布，其余区域填BGR(127,127,127)。无插值、无缩放、无裁切，原始像素和相机射线保持一致；目标GT变换不改变。没有选择公共裁切交集，因为那会裁掉819个GT实例观测条目中的部分可见框。

填充区域属于未观测区域的统一灰色近似。原四算法没有共同的无效像素掩码接口，边界附近的轮廓统计可能受填充影响；五方法采用相同策略，另外报告距原生图像边缘8px的目标分组。不能据此称与原生逐帧K实现的算法行为完全等价。

归一化实际发生在各方法每帧相机更新里，计入预处理和计算时间；没有用离线预处理缓存隐去开销。

## 4. 我们的方法在无纹理CAD上的实际状态

本包模型没有UV/diffuse贴图。保持原final的Region、视频ORB、可靠性融合、预测、方向先验和区域自适应高斯去噪；CAD-DISK仍按原final配置/模型加载，但 `Body::has_texture()` 为false，CAD匹配分支不会执行。

因此显示名明确为 `Ours (CAD-DISK inactive)`，每作业记录 `cad_disk_configured=1`、`cad_texture_available=0`、`cad_disk_executed=0`。其他方法configured为0。此条件主要验证真实弱纹理输入下其余模块及整体边界，不能用来证明模型DISK约束的真实有效性；速度变化也不能当作Full已经加速。

为保持原final“Region用滤波图、视频ORB用原图”的行为，新相机继承原LoaderColorCamera。工具仅在自己生成的覆盖头文件中增加一个输入已解码图像的公开内联方法，调用原有滤波函数，复用原有原图访问器；不改原源码文件、对象布局或算法实现。生成记录保存在 `build_inputs/generation.json`。

显示仍用llvmpipe；本组没有CAD-DISK推理，主要计算在CPU。按用户指定绑定物理3号卡，保持会话、线程和运行身份一致，不预先假定速度或排名。

## 9. 计时和审计口径

`compute_wall_us = tracking_wall_us - decode_us`。包含实际整数填充、我们的噪声估计/滤波、运动预测、全部跟踪和成功后历史状态更新；不包含PNG读取解码、评分、GT重置、模型生成、会话建立、初始叠加或CSV写入。

每帧分别记录decode、preprocessing、tracking、compute、metric、reset、frame_wall及原生cycle阶段字段。主表只展示计算均值/P95及计算FPS；JSON中的timing统计mean/median/p95单位为微秒。评分曲线属于固定0.1直径重置轨迹上的条件统计，不冒充改变阈值后重新运行的轨迹。

逐帧审计检查图号、对应GT实例、可见度、重置段、重置前估计、全部几何点的独立MSSD/MSPD和计时分解；原生与重算分类差异保留。每配置第一图只初始化，低可见度帧不删除。无效估计计失败，误差均值/分位数遇无限值会写null并报告无效计数，不丢掉其准确率分母。

RGB启动预检读取所有选中PNG头，并记录大小/mtime；模型和标注使用完整SHA256，RGB像素内容并非逐字节完整哈希。运行期间保持数据只读。原图边界和可见度分组在summary/results中单列。
