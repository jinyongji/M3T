# RBOT五方法评测与每帧计算计时

日期：2026-10-22。方法：RBGT、SRT3D、ICG、ICG+、M3T（我们这版）。

## 1. 时间展示口径

主要速度指标统一为 `compute_wall_us`：每帧预测、图像转换/算法预处理和跟踪的墙钟计算耗时，排除文件读取、PNG解码、误差评价、GT重置、初始化、模型生成、ONNX会话加载和结果写入。

```text
compute_wall_us = tracking_wall_us - decode_us
```

单位换算为毫秒后报告均值、中位数和P95；计算FPS为 `1,000,000 / mean_compute_wall_us`。它不代表包含读图的在线吞吐。算法内部的图像滤波、GPU推理等待与传输属于计算流程，不能从某一方法单独扣除。

读图与完整流程的逐帧字段仍保存在JSON/CSV中用于检查时间分解，主结果表不展示它们。不能用两个P95相减来估计计算P95，应直接使用逐帧计算时间的分布。

已有工业评测的JSON已保存这个字段，因此两份五方法本地汇总已按此口径修订，无需重跑工业数据集。进阶集我们的方法为17.764 ms/帧、计算FPS 56.29；ICG+为6.074 ms/帧。此前73.962 ms是含读图的完整流程数值，不再作为主要速度指标。

## 2. 为什么这次RBOT仍重跑我们的方法

用户给出的旧运行：

```text
/home/jyj/autodl-tmp/M3T-rbot-runs/linux_final_all_first4_20261015T091045Z_e41869dc
```

旧运行已完整完成72个配置，已有97.0708%的总体准确率。其逐帧CSV只有 `cycle_us`，缺少 `decode_us / tracking_wall_us / compute_wall_us`。

旧原生cycle可能已经排除了图像加载，但各方法的原生cycle覆盖范围不同，且不等同包含预测和算法预处理的统一计算墙钟范围。无法仅靠旧的cycle反推出缺失字段，因此旧准确率只作为参考；本次五方法全部重跑，不能将四个新计时结果与旧原生cycle直接拼表。

新驱动复用之前工业对比包中已冻结、已校验的算法源码，不修改原比较包或旧结果。我们的参数沿用该快照的final配置，关闭额外诊断采集；输入和评测壳改为RBOT格式。新驱动还沿用工业评测的有限误差保护：无效估计计为失败，`acos`数值越界夹紧；不强制新旧准确率完全相等。

## 3. 范围与公平协议

| 项目 | 本轮设置 |
|---|---|
| 物体 | RBOT全部18个物体 |
| 序列 | a_regular、b_dynamiclight、c_noisy、d_occlusion |
| 配置数 | 18×4＝72 |
| 方法作业 | 72×5＝360 |
| 图像 | 原始640×512、8-bit RGB，不缩放 |
| 相机 | fx=650.048，fy=647.183，cx=323.828，cy=256.823；沿用作者示例的半像素约定 |
| 模型与位姿单位 | 原文件毫米；模型按0.001加载，位姿另写只读输入副本转换到米，不改原文件 |
| 初始化 | 图像0000，使用该目标的真值位姿 |
| 评价 | 图像0001–1000，每配置1000个目标帧 |
| 分母 | 每方法72,000帧，五方法共360,000个方法目标帧 |
| 成功条件 | 平移≤5cm，旋转≤5° |
| 重置 | 失败帧先计入，再按该帧真值重置；导出重置前估计 |
| 遮挡信息 | 四序列均不输入已知遮挡物模型或其他物体真值；不加入额外modeled occlusion第五配置 |
| 线程/显示 | 固定单线程策略，OpenGL使用llvmpipe；DISK使用选定GPU |
| 计时预热 | 每配置前10个评价帧不计时；准确率仍包含它们 |
| 有效计时样本 | 每方法72×990＝71,280帧 |
| 方法顺序 | 按配置轮换首个方法，以分散系统缓存顺序效应 |

ICG为RGB/Region入口，ICG+为原版Region+ORB，均不是RGB-D版本。作者默认的模态参数和优化正则保持各自设置，不为追求同名参数而强制改成一个算法。
