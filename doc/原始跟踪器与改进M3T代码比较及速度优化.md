工业数据目前只有 RGB PNG 和物体 CAD、真实位姿，没有逐帧传感器深度。所以 ICG 采用其原始 RBOT 示例已有的 RGB/Region 路径；M3T 原版也按 RGB 路径运行。结果应写作 **ICG-RGB**，不能解释为完整 RGB-D ICG 的性能。原版库支持 DepthModality，不代表本次启用了深度。纹理点反投影用到的渲染深度不是传感器深度输入。

## 3. 当前工作目录相对提供的原版 M3T 的实际改动

按 `include / src / examples` 中 C++ 头文件、实现和 CMake 文件比较，忽略 CRLF/LF 差异，排除本次新建的 `examples/industrial_compare` 目录，得到 **78 个文件相同，23 个文件新增或变化**。逐文件 SHA256、增删行统计见同目录 `supplied_m3t_source_comparison.json`。Python 工具、文档、构建环境与数据不包含在这个数量内；它也不等于 23 项算法创新。

### 3.1 CAD 外观约束：新增了模型到图像的 DISK 路径

原版 M3T 的 TextureModality 已能将视频关键帧三维点与当前图像特征匹配，RBOT 默认使用 ORB。当前版保留这一分支，并增加：

1. `include/m3t/body.h`、`src/body.cpp`：保存和加载 OBJ UV、材质和 diffuse 贴图。
2. `src/renderer_geometry.cpp`：增加纹理坐标、纹理 GPU 资源和绑定。
3. 新增 `include/m3t/textured_renderer.h`、`src/textured_renderer.cpp`：按当前估计位姿渲染聚焦 CAD 颜色和深度。
4. 新增 `include/m3t/disk_feature_extractor.h`、`src/disk_feature_extractor.cpp`：通过 ONNX Runtime 调用 DISK，分别处理 CAD 渲染图和观测 ROI。
5. `src/texture_modality.cpp`：匹配及几何筛选后，把模型点通过渲染深度还原到物体坐标，形成与当前图像二维点的重投影约束。

当前 final 实际网络输入是 **128×128**，不能从 `disk_512.onnx` 文件名认定为 512×512。特征描述子为 128 维。本次默认用二维仿射 RANSAC、阈值 3 像素，未打开可选 PnP 等路径。没有重新训练 DISK，也没有使用 LightGlue。

这里增加的是 CAD 外观锚点，目标是补充仅依赖视频关键帧时的信息。模型贴图质量、合成/观测外观差异、遮挡和初始位姿都会影响有效匹配数量，不能只凭实现存在就断言准确率必然提升。

### 3.2 可靠性融合与信息互补

原版 `Link::CalculateGradientAndHessian()` 汇总各模态梯度和 Hessian。原始模态内部已有噪声建模、稳健损失等处理；不能将它描述成完全无权重、无鲁棒性。

当前 `src/link.cpp` 加入显式可靠性融合：根据有效点数、平均重投影误差，以及纹理建议更新与区域锚点更新的方向冲突调整纹理权重，同时作用于梯度和 Hessian。CAD 模型纹理还会在按正则尺度归一化的信息矩阵特征方向上补充约束：现有证据弱的方向获得较多补充，强方向较少，并结合其匹配可靠性。

这是基于观测统计和信息矩阵的规则，不是另训练的融合网络。当前 final 启用；独立贡献仍需同数据消融才能量化。

### 3.3 帧间预测和弱旋转方向的时序先验

`examples/rbot_evaluator.cpp` 新增历史位姿状态。基础外推为 `T_last * inverse(T_previous) * T_last`。与方向性时序先验一起启用且历史足够时，还会结合最近两个相对运动缓和单次估计抖动。失败真值重置后清空预测状态，避免延续错误轨迹。

`src/link.cpp` 中的方向性先验利用 Hessian 及旋转/平移耦合，提取图像约束较弱的旋转方向，再补充预测旋转信息。它没有对六个自由度统一施加强平滑。快速改变运动时，预测可能偏离，因此仍需本帧观测修正。

### 3.4 噪声自适应处理与分支输入分离

`src/loader_camera.cpp` 使用稀疏 Haar 高频响应的 MAD 统计估计噪声。当前 final 的高斯路径在估计噪声标准差大于 4 时使用 `5×5、σ=1` 滤波，区域分支读取处理后的图像，ORB 和 CAD-DISK 观测仍读取原图。

这由实际图像统计触发，不根据序列名称选择；“region-only”指滤波作用范围，噪声序列依然运行区域、视频 ORB 和 CAD-DISK。Wiener 实现也存在，但该 final 未启用。

### 3.5 评测工程、诊断和工业数据适配

新增或扩展的工程能力包括命令行配置、按序列/物体运行、逐帧位姿和融合诊断、重置前估计保存、无效姿态审计，以及 Linux 无 root 部署。工业入口补充 900×600 内参、米制 CAD/GT、500 张图像索引和 uint16 固定 `/257` 转换。

本次又加入读图、预处理、完整跟踪外层、指标计算和重置计时。对比时 `--benchmark` 关闭外部诊断文件输出，保留可靠性融合需要的内部统计；默认工业入口原有诊断行为继续可用。计时是工程测量，不算准确率算法贡献。

## 4. 参数及公平性边界

公共评测固定同一 RGB 图像、CAD、GT、尺度、首帧初始化、5 cm/5°阈值、失败重置、每目标独立跟踪和 7 次对应×2 次更新。原版方法保留其原始 RGB RBOT 参数；不会为了让数值形式相同而替换掉各方法自己的概率模型。

| 参数 | RBGT | SRT3D | ICG-RGB | M3T 原版 | 当前 final |
|---|---|---|---|---|---|
| 预计算模型点数 | 200 | 200 | 200 | 200 | 200 |
| 预计算球半径/细分 | 0.8 m / 4 | 相同 | 相同 | 相同 | 相同 |
| 区域尺度 | 5,2,1 | 5,2,2,1 | 5,2,2,1 | 5,2,2,1 | 5,2,2,1 |
| 旋转/平移正则 | 5000 / 500000 | 5000 / 500000 | 1000 / 100000 | 1000 / 30000 | 1000 / 30000 |
| 视频 ORB | 无 | 无 | 无 | 300 点、3 层、1 关键帧 | 相同基础参数 |
| CAD-DISK | 无 | 无 | 无 | 无 | 开启，128 输入 |

0.8 m 球半径是针对米制工业模型的统一预计算设置，若 CAD 最大包围直径超出 1.6 m 会报错。本次来源是 RGB RBOT 示例配置的工业适配，不是原论文 YCB/OPT 专门配置、RGB-D 配置，也不是所有算法重新调参后的最优成绩。若后续做论文级调参，应另划验证集，并将调参策略列为独立实验。

2026-10-18 小测发现并修正一项旧版适配问题：RBGT/SRT3D 的模板渲染焦距采用线性视场近似，真实包围直径不足以保证所有视角不裁切。适配器现将其 `maximum_body_diameter` 设为透视包围球对应的渲染边界，并增加 2% 光栅余量；物体几何与位姿保持原值，ICG/M3T 原有的透视视场公式沿用。完整推导和更新步骤见服务器说明第 7 节。

## 5. 速度不足：目前能确认什么

原有 v0.8 工业全量日志：当前 final **85.9639%（64344 / 74850）**；原生统计周期约 **15.50 ms**。这是旧版同时运动轨迹的数据，不能当成正在生成的新 v0.9 的结果。原生周期不含 PNG 解码和全部外层状态处理，不能直接取倒数宣称完整实时帧率。原始四方法尚未在本次统一工业协议下实测，当前没有相对原版的速度倍率或准确率增益结论。

源码核对排除了一个容易误判的问题：普通 final 的 CAD 特征与匹配位于 `corr_iteration == 0` 分支，**并不是每帧 7 次对应迭代都运行两次 DISK**。在渲染可见、特征有效的常规路径中，是本帧该分支分别处理渲染图和观测 ROI；失败重置/初始化还有关键帧开销。后续应测调用次数，而不是假定重复 14 次后删除计算。

服务器此前 OpenGL 实测为 Mesa llvmpipe，几何/贴图渲染主要占 CPU；DISK 的 ONNX 推理使用 CUDA。拥有 4090 不代表当前所有渲染自动运行在 GPU 上。此次统一速度配置固定所有方法 CPU/软件渲染线程数为 1，记录硬件、OpenGL、源码和二进制身份。

### 5.1 本次补充的时间口径

| 输出列 | 含义 | 用途 |
|---|---|---|
| `cycle_us` | 各原始算法内部步骤之和；各方法历史口径不同 | 查看各自内部变化，避免单独用于跨算法速度结论 |
| `decode_us` | PNG `imread` 解码/读取 | 判断高分辨率 16-bit 文件读取成本 |
| `preprocessing_us` | uint16 转换；当前版还包括噪声估计/滤波 | 解释额外预处理成本 |
| `tracking_wall_us` | 相机更新及算法、外层预测/状态等；不含误差计算和重置 | 完整跟踪调用开销 |
| `compute_wall_us` | 上项扣除 `decode_us`，仍含转换和预处理 | 弱化磁盘/文件缓存波动影响 |
| `metric_us / reset_us` | 计算评测误差 / 失败时真值重置 | 单独检查 reset 协议开销 |
| `frame_wall_us` | 跟踪 + 误差计算 + 失败重置 | 本次跨方法完整帧循环比较 |
| `correspondences_us` 等 | 对应、梯度/Hessian、优化、结果维护的阶段计时 | 下一步定位热点 |

时间报告给出均值、中位数和 P95，默认每配置排除前 10 个评测帧的时间；准确率仍统计全部 499 帧。首帧 GT 初始化、模型预计算、会话加载、投影图、进程启动和结果 CSV 写入不包含在完整帧循环内，进程总耗时另存。失败越多的方法重置成本通常越高，因此同时报告完整帧和扣解码后的计算时间，并保留重置列解释差异。

### 5.2 后续优化顺序：先测量，再做准确率回归

| 优先级 | 工作 | 需要证据与验证 |
|---|---|---|
| 1 | 先用本次五方法同机、同数据、空闲设备评测得到准确率和时间分解 | 停止数据变动后运行，至少对同一配置重复；保留逐帧输出 |
| 2 | 给 CAD 渲染、显存读回、两次 DISK、匹配与 RANSAC加更细计时和调用计数 | 先确认对应阶段耗时占比，避免将阶段总耗时全部归因于网络 |
| 3 | 检查 OpenGL GPU/EGL/GLX 可用性，建立所有方法一致的硬件渲染实验 | llvmpipe 是已确认配置；换后另存环境与结果，不与软件渲染混报 |
| 4 | 复用 ROI/推理张量/描述子缓冲，减少临时分配、格式转换、CPU/GPU拷贝 | 先保证数值与预处理路径一致，再比较帧率和成功率 |
| 5 | 评估两张输入合批、ONNX IO Binding 等实现变更 | 先确认当前动态输出模型及匹配坐标兼容；不能假定直接开启就变快 |
| 6 | 分析信息矩阵分解是否可复用，避免同一次更新内重复求解 | 检查 Hessian 随迭代变化的有效性，逐帧姿态回归 |
| 7 | 独立评估 CAD 约束按需触发、减少迭代/输入尺寸/点数 | 会改变精度与恢复行为，作为新变体单独跑全量与失败案例 |

以上 2–7 是依据当前控制流提出的待测方案，不是已完成加速或已证明的耗时排名。本次没有通过减少迭代、降低输入质量、删除失败帧或关闭核心改进来制造速度提升。后续建议用验证集筛选后，固定配置再评测全部工业序列，并分别报告仅相机运动和新物体运动场景。

## 6. 本次交付

`examples/industrial_compare` 提供不改原始算法源码的编译包装、四套 C++ 工业入口、当前版入口、公共输入/位姿审计、五方法串行调度、阶段时间报表、后台运行、断点续跑和源码/数据身份检查。`industrial-tracker-comparison.tar.gz` 已包含原始四套所需源码与当前版快照，上传后无需再单独上传整个 `3DObjectTracking-master`。

服务器具体路径、命令、输出位置及数据替换后的注意事项见同目录《工业数据集多算法服务器评测说明.md》。原始算法源码保持提供文件的字节内容；当前版快照仅额外修改两处 Linux ONNX 兼容性，由包内清单和补丁记录。
