# v0.9 同时运动序列：服务器渲染与现有900版替换

整理日期：2026-10-18。针对本机 `E:\渲染脚本\视频渲染-26-10-17` 的两卷新渲染包，以及服务器上已经完成评测的900×600数据集。

## 本次检查结论

新版包含5场景、每场景3个独立运动目标、5种条件，仅生成 `camera_and_objects_motion`。完整输出是25段视频、12,500张16-bit RGB PNG、75个位姿文件，共37,500条物体位姿，每段500帧、30 fps。

相机内参仍为 `fx=fy=1125, cx=449.5, cy=299.5`，900×600、零畸变；模型和位姿平移仍以米为单位。旧模型目录103个文件的SHA256与新版输入清单逐项一致，无需替换现有15个模型。

独立检查了scene_01正常与快速条件各500帧：Blender求值位姿与TXT的最大差约5×10⁻¹¹，实际投影内参与标定一致；正常条件三个目标的世界运动平均每帧约15.62 mm、7.10°，没有旧版定位夹具。这次是规定的空间刚体运动，物体会平移和连续旋转；不属于重力物理仿真。

两卷总大小5,437,942,093字节，合并后的SHA256已逐字节核验：

```text
615401ecc2fe06dfaf0dda81fafb1eb9855e513ec759e8d5d6bc516837d0b5b2
```

## 为什么需要兼容补丁

包内更新器原本寻找 `工业物体跟踪数据集-v0.8-20261015`，并要求旧内参为1800×1200。服务器当前实际使用的是：

```text
/home/jyj/autodl-tmp/industrial-render-900x600/dataset/交付物/工业物体跟踪数据集-v0.8-900x600-20261016
```

本次小型兼容包将更新器目标改到这个真实目录，要求新旧内参都为900×600，并将合并元数据中的两种运动模式分辨率都写为900×600。原有M3T评测入口因此可以继续使用原路径。

补丁只修改新版 `server_v09/installer.py`，同步更新新版输入SHA256清单，备份原安装器和清单。它保留原更新器的模型一致性检查、完整渲染校验、准备/备份/提交事务及异常回滚。重复应用补丁或重复安装相同结果会跳过一致内容。发现未知安装器改动或错误内参则停止。

## 替换范围

| 内容 | 处理 |
|---|---|
| 5场景的同时运动 images | 用新版12,500张PNG替换 |
| 5场景的同时运动 videos | 用新版25个MP4替换 |
| 5场景的同时运动 poses | 同步替换75个位姿TXT |
| 5个同时运动场景 `.blend` | 替换内容，保留旧文件名供现有路径使用 |
| 原 `camera_motion` 图像、视频、位姿、场景 | 保留 |
| 原 `objects` 模型和纹理 | 保留，替换前再次核验新旧一致 |
| 原相机K | 保持900×600的K，增加序列版本和每种运动模式的标定索引 |

**视频、PNG和位姿必须成套替换。**只换MP4会让播放内容改变而M3T仍读取旧图像；只换PNG、不换位姿会使评测使用错误真值。
