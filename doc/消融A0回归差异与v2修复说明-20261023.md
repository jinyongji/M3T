## 2. 对照源码发现的具体差别

原始ICG+的纹理模态将视频特征项直接累加到梯度和海森矩阵下三角：

```cpp
gradient_ -= (weight * diff.transpose()) * dx_dtheta;
hessian_.triangularView<Eigen::Lower>() -=
    (weight * dx_dtheta.transpose()) * dx_dtheta;
```

扩展版为分离视频/CAD项，先构造带负号的完整临时向量、矩阵，再相加。即使关闭CAD，这条累加表达式仍与原始实现不同。两种写法数学等价，但Eigen表达式求值及浮点舍入顺序可不同；跟踪的非线性迭代和失败后重置可能放大初始差别。

本地从三份真实源代码中提取梯度/海森矩阵计算循环，用固定种子的400组输入进行隔离比较：关闭CAD的200组恢复原累加后，与原始循环的梯度/海森矩阵差为0；启用CAD的200组修订前后差为0。原始与扩展版的无CAD循环确实出现非零差异。

**这确认了一个可复现的数值路径差别，尚未证明它解释了服务器上的全部A0偏差。** 用户提供的三个JSON只有汇总，不能定位每项的首次位姿分歧；服务器的实际图像、编译器及优化轨迹仍须严格回归验证。不能据此放宽容差，也不能宣布全部问题已经解决。

## 3. v2具体修改

1. 在独立消融目录中生成 `build_inputs/texture_modality.cpp`，只在关闭CAD匹配、当前观测为视频特征时恢复原始累加表达式。诊断统计保留；启用CAD的既有计算路径保留。影响无CAD变体A0、A2、A8。
2. 独立CMake目标只替换这一份编译单元；保存 `build_inputs/video_only_arithmetic.patch` 和源码身份。原冻结源码、旧五方法二进制和正在运行的T-LESS入口均不修改。
3. `ablation_state.json`记录 `video_only_original_accumulation`，逐帧审计器要求它与CAD开关对应。
4. 新的 `regression.json`额外记录前6帧位姿差、首个超容差记录、图像文件名，以及 `row_index_base: 0`，方便继续定位。原容差和分类/重置段检查不变。
5. 旧Region模板可复用，但必须核对冻结算法身份、模型生成器相关Evaluator源码、数据集lane与缓存根目录一致。无法证明一致时停止并报告，不跨不明版本复用。v1/v2生成的Evaluator头文件和实现文件已在本地逐字节比较一致。

v2使用新目录 `/home/jyj/Projects/m3t-ablation-v2`，新运行使用新时间戳。**不恢复v1失败运行，也不把v1的A1等结果拼入v2。** 本次小测仍重新执行全部九组及两个参照，只复用可验证的Region模型缓存。

P/T解耦、5cm/5°、首帧初始化、失败先计分再GT重置、读图解码排除、线程设置、九组定义和三张卡安排均沿用原设计。共享负载耗时继续只作记录，不作为正式速度结论。
