## 6. 成功率与速度的解释

成功率是平移≤0.05 m 且旋转≤5°的目标帧比例。每个目标独立跟踪；其他目标的 GT 不用于本目标跟踪或遮挡建模。姿态取自重置之前；失败/非有限估计保留在分母，失败之后才真值重置。双精度旋转投影重算用于审计，会报告和原生判定不同的帧，但不会用重算结果改写原生重置轨迹。

该指标不是检测准确率、ADD/ADD-S，也不是从第一帧到最后一帧完全无真值重置的连续跟踪成功率。对有对称性的工业件，5°指标未做对称等价修正，后续若增加 ADD-S/VSD，应作为额外指标单列。

本次用于跨算法的主时间是 `frame_wall_us`：包括读图、转换、当前版去噪、外层预测/状态维护、跟踪、误差计算和失败重置。`compute_wall_us`扣除 PNG 解码但仍包含预处理。初始化/模型生成/ONNX 会话加载、CSV 输出和进程启动不在这两个口径内，另存进程总耗时。原生 `cycle_us` 因各方法历史计时范围不同，只用于内部诊断。

所有方法固定 OpenCV/OpenMP 单线程，以及软件 OpenGL 的 llvmpipe 单线程；当前版 DISK 仍用 CUDA。以相同渲染方式和线程配置对比，不能把 llvmpipe 结果描述为硬件 OpenGL 渲染性能。运行时应尽量避免其他 CPU/GPU 密集任务争抢资源。源码检查和本机测试不能替代服务器上的实际小测；完整 Linux 链接、OpenGL 和 CUDA 运行以服务器执行为准。

RBGT、SRT3D 的位姿更新把梯度/Hessian和求解合在同一 API 中，对应 `optimization_us`；其 `gradient_hessian_us` 为 0，不能理解成不做梯度计算。该阶段结构差异也是主表比较完整帧循环而非单个内部阶段的原因。

输入指纹对校准、CAD/材质/贴图与 GT 使用完整 SHA256；为避免重复读取数十 GB 图像，对 PNG 使用 IHDR 哈希、文件大小和修改时间，实际逐帧解码在运行时完成。这足以识别常规重新渲染/替换，但不是所有图像像素的完整内容哈希。

## 7. 2026-10-18 模板视场适配修复

第一次 RBGT 小测在 `obj_000001` 第 107/2562 个模板视角报 `BodyData does not fit into image`，随后调用原版的 `cv::imshow`，在无 GUI 的 OpenCV 中中止（返回 134）。最初适配器以 `2*max(norm(vertex))` 作为旧版 `maximum_body_diameter`，在其近似焦距计算中不足以覆盖透视放大的轮廓。这是适配器对旧版本渲染边界估计不足，不需要安装 GTK 来掩盖它。

RBGT 与 SRT3D 原始生成器均采用 `f=(N-20)*R/D`。修复在适配器中为它们计算 `D=2*r/sqrt(1-(r/R)^2)*1.02`，其中 `r` 为网格相对物体原点的最大半径、`R=0.8 m`，额外 2% 用于光栅化余量。最大轮廓投影由透视包围球约束，不再依赖单纯的线性近似；还检查近裁剪面保持为正。原版 ICG/M3T 的模型生成器已有基于 `tan(asin(r/R))` 的视场计算，沿用原有设置。

此参数仅扩大旧版模型生成渲染边界；没有放大 OBJ、移动原点、修改 GT 或更改评测相机内参。导出 metadata 分别记录真实包围直径及旧版渲染直径。四套原始算法源码仍不修改。失败子进程的日志末尾现在也会直接出现在 launcher 输出中。
